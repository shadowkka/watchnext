# WatchNext: карта для ИИ и разработчиков

Прочитай этот файл прежде, чем исследовать проект. Не требуется читать все исходники для каждой задачи. Подробности — `docs/ARCHITECTURE.md`; пользовательский сценарий — `README.md`.

## Назначение

Один Python worker управляет выборочной загрузкой через qBittorrent, публикацией hardlink в Jellyfin, удалением просмотренного и общей Telegram-очередью. Отдельные фоновые задачи ищут раздачи Jackett и проверяют расписание TVmaze. Внешних Python-зависимостей нет.

## Инварианты, которые нельзя нарушать

1. **Секреты и данные пользователя не входят в Git.** Не читать и не печатать `.env`, `access.txt`, SSH-ключи, живые конфигурации, состояние и историю без необходимости. Не включать их в коммиты, PR, тесты или логи. Используй `.env.example` и синтетические значения.
2. **Безопасное удаление.** Не удалять активное воспроизведение. Сначала сохранить решение, остановить торрент, исключить файлы, убрать обе ссылки, выполнить recheck и дождаться завершения. При ошибке API/диска — остановить операции, не считать недоступный файл ручным удалением.
3. **Резервации до старта.** Сохранять выбранные файлы до включения приоритетов. Не скачивать весь сезон для получения метаданных. Полный размер выбранного файла учитывается заранее.
4. **Лимиты.** Количество считает серии (двойные — две), фильмы — ноль. ГБ общие. Снижение лимита не удаляет непросмотренное. Явная пользовательская пауза сохраняется.
5. **Остановка сидирования.** Если все выбранные файлы скачаны, торрент остановлен; при новом незавершённом выборе запускается сам. Не менять это на общую паузу worker.
6. **Изоляция фоновых запросов.** Фоновые потоки не меняют `Store`, не добавляют торренты и не удаляют файлы. Проверять актуальность задания, пользователя и generation/revision до применения результата. Ошибка поиска/расписания не останавливает медиаочередь.
7. **Подтверждение.** Подписки предлагают раздачу, но не скачивают автоматически. Импорт проходит через существующее подтверждение `search_add` и `Worker.add`.
8. **Права.** Только личные чаты владельца/приглашённых. Callback capabilities привязаны к пользователю и версии объекта; новые действия должны сохранять эту проверку. Приглашения/отзыв — только владелец.
9. **Пути и HTML.** Проверять пути через `safe_path`, запрещать symlink/traversal. Для Telegram HTML использовать `RichText` и экранировать все внешние строки. Обычные уведомления оставлять plain text. Запросы Jellyfin явно требуют `Accept: application/json; profile=PascalCase`: свежий сервер может по умолчанию вернуть camelCase.
10. **Чужие задания не забирать.** Не удалять и не перенастраивать чужие торренты. Не сбрасывать пароли существующей установки при повторном запуске installer.

## Рабочие команды

Из корня репозитория:

```bash
python3 -m unittest discover -s tests -q
python3 installer.py --help
bash -n install.sh scripts/install-docker-ubuntu.sh
# compose config читает .env; для CI используйте временную копию .env.example
docker compose config --quiet
```

Тесты `Lifecycle` содержат fake qBittorrent/Jellyfin/Telegram и временные папки. Они не должны обращаться к реальным сервисам. В некоторых тестовых классах унаследованные тесты намеренно отключены: добавляя общие тесты, учитывай это.

## Публикация и эксплуатация

- Обновляй Dockerfile и `.dockerignore`, если добавляешь runtime-модуль.
- Не копируй примеры из реального сервера в документацию. Только `IP_МИНИ_ПК`, `viewer`, синтетические ID и токены-заглушки.
- `state/state.json` — атомарный JSON, миграции добавляй через обратно совместимые defaults; не заменяй живой файл пустой заготовкой.
- Не запускай второй Telegram poller с живым токеном для проверки установщика.
- Изменения установщика проверяй на отдельном Docker project с другими портами и отдельной папкой, не на рабочей установке.
- Не добавляй cron задания или автоматизации Codex: подписки исполняет сам worker.

## Web и REST API

`server.py` запускает REST API и единственный worker (Telegram опционален). `integrations.py` хранит приватные настройки Telegram в state/integrations.json. `web/` содержит Node gateway, подборки, TMDB и адаптивный интерфейс; web-data/integrations.json хранит токен TMDB и публичный URL Jellyfin. Не добавляйте эти JSON-файлы в Git/архив исходников.

Проверки: `python3 -m unittest discover -s tests -q`, `python3 -m unittest test_server -q`, `cd web && npm test && npm run check`.

`catalog_ui.py` — меню Telegram для общего веб-каталога, `catalog_client.py` — внутренний HTTP-адаптер и разбор импорта. Проверки: `tests/test_catalog.py`. Каталог не дублировать на Python; использовать общие API Node, чтобы настройки TMDB и просмотренное совпадали. Тесты Telegram используют fake-транспорт; не отправлять пользователям тестовые сообщения. Изолированная проверка каталога не должна иметь токена Telegram или доступа к живой очереди.
