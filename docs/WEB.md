# Веб-интерфейс вместе с сервером

`./install.sh` устанавливает REST API, один worker с опциональным Telegram-ботом и веб-интерфейс в одном Docker Compose project. После установки открывайте `http://IP_МИНИ_ПК:8787`. Telegram и TMDB подключаются в настройках веб-интерфейса; для первого запуска токены не требуются.

## Настройки

- **TMDB:** API Read Access Token из аккаунта TMDB. При вводе нового токена сервер проверяет его до сохранения. Пустое поле сохраняет текущий; «Отключить» удаляет его из использования. Смена применяется без перезапуска веб-сервиса.
- **Telegram:** токен отдельного бота от @BotFather, числовой ID владельца и переключатель включения. Проверка использует getMe. Включение, выключение и смена бота применяются в единственном worker, второй poller не запускается. Старые обновления не применяются после смены экземпляра бота. Пустое поле сохраняет текущий токен.
- **Jellyfin:** необязательный публичный адрес. Без него при входе через `.local` используется `http://jellyfin.local`; при входе через IP — этот же IP и порт 8096. Для других портов, HTTPS и URL с префиксом задайте адрес явно. `.local` требует отдельного mDNS/DNS в домашней сети; установщик его не создаёт.

Токены не возвращаются API и не записываются в localStorage. Файлы `state/integrations.json` (Telegram) и `web-data/integrations.json` (TMDB, URL Jellyfin) сохраняются атомарно с правами 0600. Каталоги закрыты правами 0700. Существующие переменные Telegram из `.env` используются до первого сохранения настроек. Это панель домашней сети: используйте VPN для удалённого доступа. Если установлен API_TOKEN, он потребуется и для изменения настроек интеграций.

## Переходы в Jellyfin

Кнопка в шапке открывает Jellyfin. Кнопка в раздаче открывает сериал или фильм. Кнопка воспроизведения рядом с опубликованным эпизодом открывает карточку этого эпизода. Сервер сопоставляет точный путь опубликованного файла с библиотекой Jellyfin и возвращает только ID; ключ Jellyfin не попадает в ссылку. Автоматический запуск воспроизведения не выполняется. Если файла ещё нет в библиотеке, показывается причина. Вход в Jellyfin выполняется обычным способом.

## Запуск и обновление

```sh
# После установки; запускает и сервер, и веб:
docker compose up -d
# После обновления исходников:
docker compose up -d --build queue web
```

Порты задаются через WEB_PORT (8787) и SERVER_PORT (8000) в `.env`. Внутри Docker веб обращается к `http://queue:8000`; внешний IP не зашит в исходники. Данные веба находятся в `web-data`, очередь — в `state`, видео — в DATA_DIR. Сохраняйте все эти каталоги при переносе и обновлении. Исходники веба лежат в `web/`; никаких облачных сервисов размещения не требуется.

## Проверки

```sh
python3 -m pip install -r requirements.txt
python3 -m unittest discover -s tests -q
python3 -m unittest test_server test_integrations -q
cd web
npm test
npm run check
```

Тесты используют синтетические данные. Не запускайте второй worker с живыми Telegram-реквизитами для проверки установки. Проверку нового установочного комплекта выполняйте в отдельном Compose project с отдельными каталогами и портами.

## Быстрая выдача поиска

Веб использует POST /api/search/start и GET /api/search/jobs/{id}: ответы готовых трекеров показываются до завершения остальных. Поздние результаты добавляются в ту же выдачу; неответившие трекеры указаны явно. Фильтры сохраняются при дополнении результатов. Старый GET /api/search продолжает возвращать итоговый массив для Android и прежних клиентов.

Поиски выполняются отдельно от worker и не меняют очередь. Одновременно разрешены четыре задания, одинаковые активные запросы объединяются, завершённые задания хранятся не дольше двух минут (максимум 64). Отмена/смена запроса в браузере прекращает опрос и не применяет устаревшую выдачу. Сетевые запросы к трекерам завершаются собственным таймаутом; быстрые ответы не обрезаются ради медленного трекера.

## Telegram: те же каталог и история

В `/menu` добавлены «Что посмотреть» и «Случайный». Команды `/discover`, `/random`, `/person Имя` и `/watched` открывают соответствующие разделы. Частичное имя (например, «Том Х») возвращает варианты персон; Telegram передаёт боту отправленное сообщение, а не каждое нажатие клавиши.

Бот использует общий Node-каталог через внутренний CATALOG_URL=http://web:8787: TMDB, русские описания, обложки, Wikidata-фильмографии и семь подборок. Отдельный токен TMDB или отдельный список просмотренного не создаётся. В случайном выборе доступны годы, рейтинг TMDB, жанр/страна и исключения, 1/3/5/10 вариантов; уже просмотренные и показанные в этой подборке ID исключаются. Фильмографии/подборки листаются по шесть, фильтруются по типу, роли и годам, сортируются по дате/названию/источнику. Источники могут быть неполными.

Карточка фильма предлагает поиск раздач и отметку «Уже смотрел»; загрузка раздачи по-прежнему требует выбора и подтверждения. В поиске раздач добавлены сезонный фильтр (включая диапазоны) и сортировка по размеру в обе стороны. Быстрые результаты доступны до завершения остальных трекеров; их внутренние индексы остаются стабильными при поздних ответах. Кнопки дополнительно связаны с поколением запроса/подборки.

Владелец может загрузить через «Просмотренное» CSV/TSV/JSON (UTF-8, до 1 МБ и 20 000 строк). После разбора показывается подтверждение; распознанные строки добавляются в общий список. Импорт ссылки профиля Кинопоиска пока не реализован. Приглашённые могут смотреть каталог и отмечать фильмы, но массовый импорт доступен владельцу.

В «Раздачи и файлы» у опубликованного фильма/сериала и серий появляются переходы в Jellyfin. Ссылки содержат только ID, требуют обычного входа Jellyfin и используют адрес из веб-настроек; по умолчанию — IP домашнего сервера и порт Jellyfin. Владелец также может открыть общие настройки интеграций из меню бота. Для ссылки на веб используются WATCHNEXT_PUBLIC_URL либо BIND_IP/WEB_PORT; для стандартной установки значения задаёт установщик. Локальные ссылки доступны из домашней сети или через настроенный VPN.

Каталог выполняет не более четырёх фоновых запросов (два одновременно). Фоновые потоки не меняют Store или очередь; результаты применяются главным worker только для актуального пользователя и сессии. Во время UI-заданий Telegram long polling сокращается до одной секунды, в простое сохраняется исходный интервал. Второй poller не запускается.

## Настройки и обновления

Серверные лимиты берутся из `/api/status`, а не из localStorage браузера.
Сохранение отправляет только отредактированные лимиты; новое подключение сначала
загружает настройки выбранного сервера. `POST /api/limits` трактует отсутствующее
поле как «не менять», `capGb: null`/0 как снятие ограничения. Вся запись
валидируется до изменения состояния. Интервал обновления хранится в web-data/integrations.json и общий для браузеров
и Android. В localStorage остаются адрес, демо-режим и резервный интервал для
автономного клиента без шлюза; токен API остаётся в sessionStorage.

Обновляйте код/образы без удаления `state/`, `web-data/` и `.env`. Compose
монтирует эти папки отдельно от образов. Данные Telegram/TMDB, история и лимиты
не должны входить в архив исходников или заменяться установочными примерами.

Android-оболочка общего веба и инструкции сборки: [android/README.md](../android/README.md).

В сети search_dns адреса DNS, Jackett и FlareSolverr закреплены отдельно через SEARCH_DNS_IP, SEARCH_JACKETT_IP, SEARCH_FLARESOLVERR_IP. Это предотвращает захват адреса DNS динамическим клиентом после перезапуска Docker. Для своей подсети изменяйте все три адреса; установщик вычисляет адреса клиентов при выборе подсети.
